## 1. What the reference project did (baseline) and where it falls short

Reference: `Full_Pipeline.ipynb`, `report/Object_Tracking.pdf` (Joe Doan, Cory Stever, Ibrahim Alborno, Apr 2026).

Pipeline: `Frame -> Mask R-CNN (R50-FPN) -> crop -> Siamese ReID (R50 + BN-neck, 256-d) -> Hungarian (0.5 IoU + 0.5 cosine) -> IDs -> video`

| Baseline gap | Evidence | Our improvement |
|---|---|---|
| Two-stage 2017 detector, slow, reduced to 384x640 | `report.md` 2.1.1 | YOLO26 (Ultralytics) or RT-DETR/RF-DETR, full-res |
| DeepSORT-style, **no motion model** (no Kalman) | report 4.2 | ByteTrack / BoT-SORT (Kalman + camera-motion compensation + low-score second association) |
| **No MOTA / IDF1 / HOTA** - only "22 IDs, 525 frames" | report 4.2 | Evaluate with TrackEval on MOT16 train sequences |
| Evaluated on one sequence (MOT16-09) | report 4.2 | Evaluate on all 7 train sequences, report the hard one (MOT16-03/04) separately |
| ReID trained on Market-1501 only (domain gap) | report 4.2 | OSNet / pretrained ReID weights, optional fine-tune on MOT16 crops |
| Inconsistent numbers: README says 40 epochs / val loss 0.3783, report says 6 epochs / 0.2876; course PDF says Faster R-CNN, report says Mask R-CNN | README vs report | One config file, one results table, all numbers regenerated by us |
| Masks computed but unused for tracking | report 3.5 | Optional stretch: SAM 2 mask propagation for true MOTS |

**Honest framing for the presentation:** we are not claiming to beat MOT16 leaderboards. The claim is "same task, modern components, properly measured, with an ablation showing which change helped how much."

## 2. Target system

```
Video -> Detector (YOLO26 / RT-DETR) -> Tracker (BoT-SORT or ByteTrack, Kalman + CMC)
                                     \-> ReID embeddings (OSNet) ----^
      -> MOT-format txt -> TrackEval (MOTA, IDF1, HOTA, IDsw) -> annotated MP4
```

Ablation grid (this is the core experiment, and gives you real numbers for the final report):

| ID | Detector | Tracker | ReID | Purpose |
|---|---|---|---|---|
| B0 | Mask R-CNN (reference ckpt) | Hungarian IoU+cos (their code) | Siamese R50 | Reproduce baseline |
| E1 | YOLO26 fine-tuned | ByteTrack | none | Detector + motion model only |
| E2 | YOLO26 fine-tuned | BoT-SORT | none (CMC only) | Add camera-motion compensation |
| E3 | YOLO26 fine-tuned | BoT-SORT / DeepOCSORT | OSNet | Add appearance |
| E4 (stretch) | best of above | + SAM 2 masks | - | MOTS-style output |

Tool choices (verified current as of Oct 2026 via Ultralytics docs and BoxMOT; confirm versions with `pip index versions` before pinning):
- **Ultralytics** (YOLO26 detect/seg; built-in `model.track()` with BoT-SORT/ByteTrack, newer builds also OC-SORT, Deep OC-SORT).
- **BoxMOT** - pluggable trackers (ByteTrack, BoT-SORT, StrongSORT, DeepOCSORT, HybridSORT) with ReID weights.
- **TrackEval** - official HOTA/CLEAR/Identity evaluator (what MOTChallenge uses).
- Field consensus: ByteTrack / OC-SORT / BoT-SORT replaced DeepSORT as defaults, and HOTA is preferred over MOTA.

### Likely Q&A (prepare 30-second answers)
1. Why Hungarian algorithm? - optimal one-to-one assignment on the cost matrix, O(n^3).
2. Why does a Kalman filter help? - predicts box during occlusion/missed detection, so IoU still works.
3. What is ByteTrack's trick? - keeps low-confidence detections for a second association pass instead of discarding them.
4. Why triplet loss vs classification? - learns a metric space; generalises to unseen identities.
5. MOTA vs IDF1 vs HOTA? - MOTA is detection-dominated; IDF1 measures identity consistency; HOTA balances detection, association, localisation.
6. Why split by sequence? - frame split leaks near-identical frames into validation.
7. Online vs offline tracking? - see course slides; we use online trackers but could add offline smoothing.

## 7. Evaluation protocol

- Metrics: HOTA, MOTA, IDF1, IDsw, FPS, via TrackEval on MOT16 train sequences (labels are public; the test set requires a server submission).
- Report per-sequence; MOT16-03 and -04 are crowded and are where ReID/CMC should matter.
- Hold-out: train the detector on sequences other than the one you evaluate. Never evaluate a detector on frames it was fine-tuned on.
- Course rubric deliverables: source code (no weights), video of target pedestrian on MOT16 **test** data (MOT16-01/03/06/07/08/12/14 - run inference only), LaTeX PDF with abstract, method, challenges, self-evaluation, citations. Reuse `dev/report.tex` as the template.
